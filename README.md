## 🚀 Git 커밋 메시지 규칙

모든 커밋 메시지는 **Conventional Commits** 형식을 따릅니다.

**형식:** `타입(스코프): 제목`

- **제목**: 명령형으로 작성하며, 마침표(.)를 붙이지 않습니다.
  - (O) `feat: 로그인 기능 추가`
  - (X) `feat: 로그인 기능 추가함`

---

### 📌 타입 (Prefix)

| 타입 (Prefix)  | 설명                                                  |
| :------------- | :---------------------------------------------------- |
| **`feat`**     | 새로운 기능 추가                                      |
| **`fix`**      | 버그 수정                                             |
| **`style`**    | 코드 포맷팅, 세미콜론, 공백 등 (기능 변경 **X**)      |
| **`refactor`** | 코드 리팩토링 (기능 변경 **X**)                       |
| **`docs`**     | README.md 등 문서 수정                                |
| **`chore`**    | 빌드, 패키지 매니저, 설정 파일 변경 (자잘한 작업)     |
| **`test`**     | 테스트 코드 추가 또는 수정                            |
| **`ci`**       | CI/CD 관련 설정 변경                                  |
| **`build`**    | 빌드 시스템 또는 외부 종속성 변경 (e.g., npm install) |
| **`perf`**     | 성능 개선                                             |
| **`revert`**   | 이전 커밋으로 되돌리기                                |

---

### ✅ 예시

```bash
git commit -m "style: Prettier 설정 적용 및 전체 코드 포맷팅"
```
